# PRD — 사업자카드 이용내역 연동 (미분류 lump 분해)

- 상태: **구현 완료 · 운영 중** (파서·업로드·정산 UI·집계규칙 전체) — 2026-07-15 현행화
- 작성: 2026-07-05
- 관련: `자금 흐름`(Sankey), `통장 현황`, `거래 분류`, 관리손익(발생주의) 방향

## 1. 배경 / 문제

통장 내역에서 `신한카드 결제 -15,998,790` 같은 **카드대금 결제**는 한 줄의 정산 건이지만, 실제로는 그 안에 원두·우유·부자재 등 수십 건의 지출이 들어 있다. 통장만으로는 이 lump이 통째로 **미분류**로 남아 자금 흐름/손익에서 미분류가 지출의 대부분(예: 80%)을 차지하고, 정확한 손익 파악이 불가능하다.

**해결:** 월 1회 사업자카드 **이용내역(엑셀)**을 업로드하면, 그달 카드결제 lump을 **개별 사용내역으로 대체**하고, 각 건을 지금의 거래 분류와 동일하게 카테고리로 분류한다. → 미분류 해소 + 정확한 손익.

## 2. 목표 / 비(非)목표

**목표**
- 카드 이용내역을 업로드해 카드결제 lump을 실제 지출 건으로 분해·분류
- 현금흐름(통장)과 손익(자금흐름/대시보드)의 역할을 명확히 분리
- 카드결제 lump의 손익 **중복계상 방지**
- 기존 거래분류/규칙엔진/AI/미분류잠금 파이프라인 재사용

**비목표(2차 이후)**
- 할부 정식 배분(구매월 전액 인식 + 결제스케줄 분리)
- 복수 카드 운영 UI(데이터 모델만 열어둠)
- POS 기반 매출 인식·채널수수료 등 관리손익 전체 전환(별도 상위 과제)

## 4. 데이터 모델

### 4.1 `finance.transactions` (확장)
- `source text not null default 'bank'` — `'bank' | 'card'`
- `card_issuer text` — 카드 발급사/별칭 (예: `'신한'`) · 복수카드 대비, MVP는 신한 고정
- `is_installment boolean not null default false` — 할부 표시(배지용, 특별처리 없음)
- 카드 행: `source='card'`, `bank`는 발급사와 무관하게 `card_issuer` 사용, `tx_at`=**사용일**, `memo`=가맹점명, `amount_out`=사용금액, `amount_in=0`
- dedup 지문: 카드도 동일 방식(일시+금액+가맹점+식별자). 재업로드 중복 차단

### 4.2 `finance.uploads` (확장)
- `source text not null default 'bank'` — `'bank' | 'card'`
- `card_issuer text`
- `settled_tx_id bigint references finance.transactions(id)` — 이 카드 이용내역이 **정산(대체)하는 은행 카드결제 건**
- `statement_total bigint` — 사용내역 합계(정산 배너·차액 계산용)

### 4.3 계정과목 seed
- `excluded › 카드대금정산` (`in_pnl=false`) 추가 — 은행 카드결제 lump 전용
- 규칙: `normalized_key='신한카드'` → `카드대금정산` 자동채움(단, **연결 확정 시에만** 손익 제외 발동)

## 5. 집계 정합성 규칙 (핵심)

| 뷰 | 포함 규칙 |
|---|---|
| **통장 현황(현금)** | `source='bank'` 만. (카드 사용행 제외 → 현금 중복 방지). 카드결제 lump은 현금 출금으로 포함. 순증감 = 통장과 일치 유지 |
| **자금 흐름/대시보드(손익)** | `source='card'`(분류된 사용내역) + `source='bank'` 중 **카드대금정산·손익제외 제외** 나머지. 월 귀속=`tx_at`(카드는 사용일) |

- **중복 방지:** 카드결제 lump이 연결되면 `카드대금정산(손익제외)` → 손익에서 빠지고, 사용내역이 대체.
- **미연결 lump:** 손익제외 미발동 → 미분류로 손익에 남음(과소계상 방지, 첨부 유도).
- ⚠️ **뷰 성격 변경:** 현재 자금 흐름은 "총유출=통장순증감(현금)". 본 기능으로 자금 흐름은 **손익 기준**으로 이동(카드 대체·손익제외 반영)하며, 통장 일치 역할은 `통장 현황`이 전담. → 자금 흐름 라벨/설명을 **관리손익(발생주의)** 성격으로 정리 필요(네이밍 재검토 항목).

## 6. 사용자 흐름

1. **업로드** — 업로드 화면에 소스 선택 `은행(신한/우리) / 카드(신한카드)` 추가. 카드 선택 시 엑셀 업로드 → 파싱 미리보기(일자·가맹점·금액·건수·합계).
2. **자동 매칭(정산)** — 저장 시 그달 은행 카드결제 후보 자동 제시:
   > `신한카드 6월 이용 N건 · 합계 ₩15,998,790  ↔  7/15 신한카드 결제 ₩15,998,790  ✅ 일치` (차이 있으면 `차액 ₩X` 표시)
   - 사용자 **확인 1번** → 은행 카드결제 건 `카드대금정산` 잠금 + `settled_tx_id` 링크 + 카드 사용행 편입.
   - 대응 결제건 없으면 `미연결(결제 대기)`로 저장(카드행은 손익 사용월 반영).
3. **분류** — 거래 분류 화면에 카드 사용행이 일반 행처럼 추가(`💳 신한카드` 배지, `신한카드만 보기` 필터). 카테고리 드롭다운·규칙학습·AI·미분류잠금 그대로. 상단 **정산 배너**로 합계/차액/상태 표시.
4. **뷰 반영** — 통장현황: 카드결제 1건 출금 그대로. 자금흐름/대시보드: lump 대신 사용내역 카테고리들이 반영 → **미분류 급감**, 재료비/판관비 등 실제 구조 노출. 카드결제 노드 클릭 시 카드 내역으로 드릴다운.

## 7. 상태/엣지케이스

- **차액(합계≠결제액):** 경고 배너만, 진행 허용. 손익은 사용내역 기준. 필요시 카드 행 수동추가(예: 연회비→지급수수료).
- **미첨부 lump:** 미분류 유지 + `💳 이용내역 첨부 필요` 뱃지(거래분류·자금흐름 미분류 노드).
- **미연결 이용내역:** `미연결(결제 대기)` 상태, 손익엔 사용월 반영, 현금엔 영향 없음.
- **할부:** 엑셀에 나온 대로 한 건씩 분류(`is_installment` 배지만). 정식 배분 2차.
- **복수카드:** MVP 신한 1개. `card_issuer` 필드로 확장 대비.
- **재업로드:** dedup 지문으로 중복 차단, "신규 N/기존 M" 미리보기(은행과 동일).

## 8. 범위 / 단계
