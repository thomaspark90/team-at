## 0. 한 줄 규칙 (2026-08-31 대표 확정)

> **매출을 "보여줄" 때는 부가세 포함(총액), 손익을 "계산할" 때는 공급가액(순액).**

왜 갈랐나 — 화면의 매출은 POS(토스·페이히어) 화면과 눈으로 대조되는 숫자여야 하고(토스 '실매출'은 VAT 포함),
손익은 매출과 매입을 같은 순액 기준으로 맞춰야 이익률이 왜곡되지 않는다. 예전에는 둘 다 순액이라
지표 매출이 POS 화면보다 8~9% 작아 "매출이 왜 다르냐"는 오해가 반복됐다.

**절대 금지**: 한 화면·한 차트 안에서 두 기준을 섞는 것. 총액 축에 순액 값을 그리려면 반드시 환산한다.

## 1. 매출

### 1.1 POS 실매출 = 상품 매출 + 선수금 판매

```
POS 실매출(총액) = pos_sales.gross  +  pos_gift_sales.gross
                   (상품 매출)          (선불권·금액권 / 식권)
```

- 파서는 상품권(금액권·선불권·식권) 행을 **상품 매출에서 빼고** `pos_gift_sales`에 따로 담는다(선수금).
- 화면에서 매출을 볼 때는 둘을 **다시 더한다** — `finance.dashboard_pos` 뷰가 union 으로 합쳐 준다.
- 검증(2026-08-31, 가든 양재천 — 토스 '매출현황' 화면과 원 단위 일치):

  | 월 | 상품 매출 | 선불권 | 합계 = 토스 실매출 |
  |---|---|---|---|
  | 2026-05 | 48,111,553 | 259,637 | 48,371,190 |
  | 2026-06 | 59,729,820 | 1,153,700 | 60,883,520 |
  | 2026-07 | 56,803,020 | 2,753,100 | 59,556,120 |
  | 2026-08 | 83,379,117 | 354,810 | 83,733,927 |

### 1.2 선수금(선불권·식권)을 판매 시점에 매출로 잡는 이유

고객이 **쓸 때** POS 상품 행은 찍히되 실판매금액이 **0원**이다(전액 차감). 그래서 판매 시점에
인식해야 매출이 누락되지 않고, 이중계상도 생기지 않는다. (2026-08-20 대표·매니저 확정,
2026-08-31 가든 브런치바 선불권 결제 3건으로 재확인)

- 브랜드별 표기: 스탭밀 = **식권 판매**, 가든 = **선불권 판매**(가든엔 식권 제도가 없다).
  `lib/finance/types.ts` `giftSaleLabel(brand)`. DB의 category 값(`'식권판매'`)은 매칭용이라 바꾸지 않는다.

### 1.3 공급가액(순액) 환산

```
supply = gross − vat   (품목별 부가세액을 실제로 뺀다)
```

`gross ÷ 1.1` 이 **아니다** — 면세 품목(일부 베이커리 등)은 부가세가 0이라, 나눗셈으로 처리하면
면세분까지 깎인다. 실효 비율은 월마다 다르다(가든 양재천 2026-08 기준 총액÷순액 ≈ 1.100).

## 2. 손익 (전부 공급가액 기준)

```
EBIT = 매출(순액) − 매출원가(cogs) − 판관비(sga) − 채널수수료
당기순이익 = EBIT + 영업외수익 − 영업외비용
영업이익률 = EBIT ÷ 매출(순액)
```

- **과세 매입은 ÷1.1로 순액 처리**, 면세 항목(인건비·이자·수도·세금 등)은 그대로. 과세 여부는 설정›계정과목.
- **손익에서 빼는 것**: 자본적지출, 보증금, 내부이체, **부가세 납부(예수금 정산)**.
  부가세 납부를 비용으로 두면 매출·매입을 이미 순액으로 잡은 뒤 또 빼는 이중 차감이 된다(2026-08-21 수정).
- **카드대금·간편결제**: 명세와 대사된 인출은 지출에서 빼고 세부 건으로 대체(`cardOffset.ts`).
  대사 안 된 덩어리는 '카드 지출(미분해)'로 지출에 포함 — 이익 과대평가 방지.
- **미분류·미상 지출은 비용에 포함**(이익 과대 방지), **미분류 입금은 매출에 넣지 않는다**(대출·자본유입일 수 있음).
- 감가상각 미반영(EBIT = EBITDA). 별도 차트에서 자본적지출 5년 정액 상각을 뺀 값을 함께 본다.
- 기말재고 조정은 **관리손익에서만** 반영(지표 재료비 = 당월 매입).

### 2.1 손익분기 매출(BEP)

```
BEP(순액) = 고정비 ÷ (1 − 변동비율)          변동비율 = 변동비 ÷ 매출(순액)
BEP(총액 축에 그릴 때) = BEP(순액) × (그 달 매출 총액 ÷ 매출 순액)
```

고정/변동 구분은 계정과목의 `cost_nature`를 따른다. 채널수수료는 변동, **미확정(미분류·미상·카드
미분해)은 어느 쪽에도 안 섞는다** — 섞으면 손익분기선이 근거 없이 부풀어 오른다.

### 2.2 원가 구조

```
재료비율 = 재료비 ÷ 매출(순액)
인건비율 = 인건비 ÷ 매출(순액)
Prime Cost = (식자재 + 인건비) ÷ 매출(순액)     ※ 포장재 제외 — 관리손익과 같은 정의
```

## 4. 그램 단위 판매 (가든 양재천 '브런치바')

```
그램 = 정가(list_price) ÷ 그램당 단가        브런치바: 30원/g (100g당 3,000원, VAT 포함)
평균 그램 = 총 그램 ÷ 판매 건수(접시 수)
```

- **정가**를 쓴다. 실판매금액(gross)으로 재면 **할인·선불권 결제에서 담은 양이 사라진다**
  (2026-08 실측: 전체할인 16건 · 선불권 전액결제 10건 → 그 행들이 0g이 된다).
- 단가표는 `lib/finance/gramProducts.ts` 한 곳. 단가가 바뀌면 `from` 과 함께 **새 구간을 추가**한다
  (덮어쓰면 과거 기간의 그램이 통째로 틀어진다).
- 브런치바 단가는 2026-08-31 기준 개시일(2026-08-05)부터 변동 없음(전 기간 정가가 30의 배수).
  같이 파는 보울(스프/시리얼/요거트)은 **2026-08-14에 3,000원 → 5,000원 인상** — 별도 상품이라
  브런치바 그램 계산에는 섞이지 않는다.

## 5. 날씨 × 매출

```
ln(일 매출) ~ 기온밴드 + 강수밴드 + 공휴일 + 요일 + 선형 트렌드   (OLS)
효과(%) = exp(계수) − 1        유의 판정: |t| ≥ 2
```

- 기준(레퍼런스) = 관측일이 가장 많은 기온 밴드 + 비 1mm 미만인 날 + 평일.
- 계산은 `/api/garden-weather-sales`가 하루 한 번(Blob 캐시 24h). **지표는 그 결과를 읽기만 한다** —
  재계산하면 전 기간 POS 스캔 + Open-Meteo 아카이브 조회로 로딩이 수십 초 밀린다.
- 2026-08-31 실측: 폭우(20mm+) 매출 −29%(양재천)·−33%(판교), 저온(판교 영하 −39%·0–10° −32%),
  폭염(판교 30°+ −17%), **비 1–20mm는 효과 없음**.
