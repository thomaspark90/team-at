# PRD — 가든 오픈·마감 체크리스트

- 상태: **구현 완료 · 배포 전** (2026-11-06 빌드 통과, 로컬 미커밋, 운영 DB 미적용, 실제 휴대폰 미검증)
- 작성: 2026-11-06 (grill-me 13문항 결정 반영)
- 원본: 구글 시트 `[Garden Service] 마감 메뉴얼`, `GS] 음료 Summary`의 프랩 레시피
- 관련: 근무 스케줄(`/garden/schedule`), 직원 명부(`/garden/schedule/staff`), docs/simple-accounts.md

## Problem Statement

매장의 오픈·마감 업무는 구글 시트 매뉴얼에 적혀 있지만, 근무 중에 그 시트를 보며 일하지 않는다. 그래서 다음 문제가 생긴다.

- 그날 무엇을 했는지 기록이 남지 않아, 빠진 일을 나중에 확인할 수 없다.
- 매뉴얼 판본끼리 내용이 다르다(샤워스크린 결합 시점, 호퍼·커틀러리 세척 주기 등).
- 인수인계가 말로 이뤄져, 사람이 바뀌면 업무 기준도 함께 흔들린다.
- 여러 명이 같은 시각에 출근하는 날은 책임이 흐려진다.

## Solution

직원이 개인 휴대폰으로 로그인하면, 근무표에 따라 그날 맡은 오픈 또는 마감 체크리스트가 자동으로 보인다. 같은 조는 한 장을 함께 채우고, 책임자 한 명이 제출까지 책임진다. 지정한 항목은 앱 안 카메라로 찍어야 완료된다.

운영진은 날짜별로 제출 현황과 기록을 보고, 코드 수정 없이 항목을 관리한다. 판교에서 2주 시범 운영을 거친 뒤 기준을 충족하면 양재천으로 넓힌다.

## User Stories

### 직원 — 확인과 체크

1. 근무 직원으로서, 로그인하면 오늘 내 담당 체크리스트만 보고 싶다. 내가 할 일을 바로 알 수 있기 때문이다.
2. 근무 직원으로서, 오늘 담당이 아닐 때는 그렇다고 안내받고 싶다. 앱 오류로 오해하지 않기 위해서다.
3. 근무 직원으로서, 항목이 구역별·작업 순서대로 나오길 원한다. 매장을 돌며 순서대로 처리할 수 있기 때문이다.
4. 근무 직원으로서, 휴대폰에서 한 손으로 큰 터치 영역을 눌러 체크하고 싶다. 작업 중에도 빠르게 기록하기 위해서다.
5. 근무 직원으로서, 잘못 누른 체크를 제출 전까지 되돌리고 싶다. 실수를 고치기 위해서다.
6. 근무 직원으로서, 진행 개수를 보고 싶다. 얼마나 남았는지 알기 위해서다.
7. 근무 직원으로서, 오늘이 해당 요일이거나 해당 월인 주간·월간 업무도 같은 목록에서 보고 싶다. 별도 일정을 외우지 않기 위해서다.
8. 근무 직원으로서, 못 한 항목에 사유를 남기고 싶다. 이유 없이 빠진 것처럼 보이지 않기 위해서다.
9. 같은 조 직원으로서, 동료가 체크한 항목과 체크한 사람, 시각을 보고 싶다. 같은 일을 두 번 하지 않기 위해서다.

### 직원 — 사진

10. 근무 직원으로서, 사진 필수 항목을 누르면 앱 카메라가 바로 열리길 원한다. 다른 앱으로 오가지 않기 위해서다.
11. 근무 직원으로서, 찍은 사진을 확인하고 다시 찍고 싶다. 흔들리거나 대상이 빠진 사진을 내지 않기 위해서다.
12. 근무 직원으로서, 카메라 권한이 꺼져 있거나 카카오톡 앱 안 브라우저처럼 카메라를 못 쓰는 환경이면 해결 방법을 안내받고 싶다. 현장에서 막히지 않기 위해서다.
13. 근무 직원으로서, 사람이 나오지 않게 찍으라는 안내를 보고 싶다. 동료나 손님이 찍히지 않게 하기 위해서다.

> **운영 상태(2026-11-06 대표 결정):** 담당 지정(조·책임자·책임 넘기기·대신 맡기)은 **꺼 둔다**(`lib/checklist/logic.ts` `CREW_ASSIGNMENT = false`). 정착되기 전까지는 그 지점 재직자 누구나 오늘 체크리스트를 열어 체크·제출한다. 아래 14~28번은 켤 때 다시 살아난다.

### 책임자와 제출

14. 조의 책임자로서, 내가 오늘 책임자임을 화면에서 알고 싶다. 제출 책임을 분명히 하기 위해서다.
15. 조원으로서, 내가 책임자가 아니어도 체크할 수 있길 원한다. 일한 사람이 바로 기록하기 위해서다.
16. 책임자로서, 전 항목이 처리되면 제출하고 싶다. 그날 업무를 끝냈음을 남기기 위해서다.
17. 책임자로서, 남은 항목이 있으면 제출이 막히고 그 개수를 보고 싶다. 빠뜨리지 않기 위해서다.
18. 책임자로서, 사진 필수 항목은 사진 또는 못 한 사유 없이 처리되지 않길 원한다. 기록의 기준을 지키기 위해서다.
19. 책임자로서, 내가 일찍 퇴근해야 하면 제출 전에 다른 조원에게 책임을 넘기고 싶다. 제출이 끊기지 않기 위해서다.

### 근무표와 다른 날

20. 대타 직원으로서, 근무표에 내 이름이 없어도 `오늘 오픈(또는 마감) 대신 맡기`를 눌러 체크하고 싶다. 운영진이 근무표를 고치기 전에도 기록하기 위해서다.
21. 해당 지점 직원으로서, 담당이 없는 날에도 대신 맡을 수 있길 원한다. 그날 기록이 통째로 비지 않기 위해서다.
22. 운영진으로서, 누가 언제 대신 맡았는지 보고 싶다. 근무표와 실제가 달랐음을 알기 위해서다.
23. 운영진으로서, 대신 맡기가 근무표를 자동으로 바꾸지 않길 원한다. 근무 기록은 따로 판단해 고치기 위해서다.

### 운영진 — 조 구성

24. 운영진으로서, 시각 기준으로 자동 제안된 오픈조·마감조를 그대로 쓰고 싶다. 평소에는 입력이 늘지 않게 하기 위해서다.
25. 운영진으로서, 특정 날짜의 조에서 사람을 빼거나 더하고 싶다. 같은 시각에 출근해도 오픈 업무를 하지 않는 사람이 있기 때문이다.
26. 운영진으로서, 자동 선정된 책임자를 바꾸고 싶다. 그날 사정에 맞추기 위해서다.
27. 운영진으로서, 직원에게 `매니저`, `서브 매니저` 태그를 붙이고 싶다. 이들이 책임자로 우선 선정되게 하기 위해서다.
28. 운영진으로서, 태그가 없는 조에도 책임자가 자동으로 정해지길 원한다. 책임자 없는 날을 만들지 않기 위해서다.
29. 운영진으로서, 근무표 주간 배포 후에 배정이 적용되길 원한다. 작성 중인 계획이 직원에게 보이지 않게 하기 위해서다.

### 운영진 — 현황과 기록

30. 운영진으로서, 날짜별 지점·조의 제출 상태와 `n/전체`를 보고 싶다. 하루 상태를 빠르게 파악하기 위해서다.
31. 운영진으로서, 자정이 지난 미제출 건이 `미제출`로 표시되길 원한다. 빠진 날을 놓치지 않기 위해서다.
32. 운영진으로서, 항목별 수행자, 시각, 못 한 사유, 사진을 보고 싶다. 문제가 생겼을 때 경위를 확인하기 위해서다.
33. 운영진으로서, 당일에 잘못 제출된 건을 `다시 열기` 하고 싶다. 실수를 바로잡기 위해서다.
34. 운영진으로서, 다시 연 사람과 시각이 남길 원한다. 기록을 믿을 수 있게 하기 위해서다.
35. 운영진으로서, 지난 날짜의 기록이 고정되길 원한다. 나중에 체크해서 기록을 꾸미지 못하게 하기 위해서다.
36. 운영진으로서, 오늘 배정자 중 계정이 연결되지 않은 사람을 보고 싶다. 담당이 앱을 못 여는 상황을 막기 위해서다.

### 운영진 — 항목과 계정

37. 운영진으로서, 항목의 문구, 구역, 세부 설명, 주기, 순서를 앱에서 고치고 싶다. 개발을 기다리지 않기 위해서다.
38. 운영진으로서, 항목별로 `사진 필수`를 켜고 끄고 싶다. 필요한 곳에만 증빙을 받기 위해서다.
39. 운영진으로서, 항목을 끄되 과거 기록은 남기고 싶다. 현재 목록과 지난 기록을 함께 지키기 위해서다.
40. 운영진으로서, 항목을 고쳐도 이미 제출된 기록은 변하지 않길 원한다. 그날 기준을 그대로 남기기 위해서다.
41. 운영진으로서, 지점별로 항목을 따로 관리하고 싶다. 판교와 양재의 구조와 운영이 다르기 때문이다.
42. 운영진으로서, 명부의 직원과 로그인 계정을 직접 연결하고 싶다. 이름이 달라도, 구글 계정이어도 배정이 정확하게 하기 위해서다.
43. 운영진으로서, 이름이 같은 계정을 연결 후보로 제안받고 싶다. 연결 작업을 줄이기 위해서다.
44. 운영진으로서, 이름을 바꿔도 연결이 유지되길 원한다. 조용히 배정이 끊기는 일을 막기 위해서다.
45. 운영진으로서, 퇴사자의 접근이 막히고 기록은 남길 원한다. 이력을 보존하면서 권한을 정리하기 위해서다.

### 사진 보관과 권한

46. 운영진으로서, 사진이 90일 뒤 자동 삭제되고 체크 기록은 남길 원한다. 사람이 찍힌 사진을 무기한 쌓지 않기 위해서다.
47. 운영진으로서, 삭제된 사진에 `보관 기간 지남`이 표시되길 원한다. 누락과 구분하기 위해서다.
48. 대표로서, 체크 사진은 운영진과 그날 같은 조만 보길 원한다. 불필요한 공개를 막기 위해서다.

## Implementation Decisions

### 배정과 책임

- 배정은 그날의 실제 근무(실제 기록이 있으면 그것, 없으면 배포된 계획)에서 계산한다.
  - 자동 제안: 가장 일찍 시작한 사람 전원 = 오픈조, 가장 늦게 끝나는 사람 전원 = 마감조.
  - 운영진 수정: 날짜·지점·조별로 사람 추가·제외, 책임자 지정을 저장해 자동 제안 위에 덧씌운다.
- 책임자 자동 선정 순서: 로그인 가능한 계정 → `매니저` → `서브 매니저` → 입사일 → 이름. 입사일이 비어 있으면 뒤로 보낸다. 계정이 없는 사람이 책임자가 되면 아무도 제출할 수 없어 계정 유무를 먼저 본다.
  - 책임 태그는 근무 역할(바리스타·콜드 등)과 분리해 직원 명부에 둔다.
- 같은 조는 한 장을 함께 채운다. 조원 누구나 체크할 수 있으며, 제출은 책임자가 한다. 운영진은 대리 제출할 수 있다.
- 대신 맡기: 해당 지점 재직 직원(소속 지점 또는 계정에 지정된 지점)이 그날 그 조에 합류한다. 근무표는 바꾸지 않으며 맡은 사람과 시각을 기록한다.
  - 맡은 사람이 책임자가 된다. 자리를 비운 사람에게 제출이 묶이지 않게 하기 위해서다. 조원도 같은 방식으로 `책임 맡기`를 할 수 있다.
- 책임 넘기기: 제출 전 책임자 또는 운영진이 조원에게 넘긴다.
- 양재천 월요일은 정기 휴무로 체크리스트를 만들지 않는다.
- 개인과 계정의 연결 정본은 직원 명부의 계정 연결 값이다. 이름 일치 판정은 쓰지 않고 연결 후보 제안에만 쓴다.

### 기록 규칙

- 체크는 당일(KST) 자정까지 가능하다. 퇴근 후 체크를 막지 않되 체크 시각을 남긴다.
- 지난 날짜는 수정할 수 없고, 미제출은 그대로 `미제출`과 진행 개수로 표시한다.
- 제출 시점의 항목 목록을 함께 저장해 이후 항목 수정의 영향을 받지 않게 한다.
- 제출 후 수정은 운영진의 당일 `다시 열기`로만 가능하며, 수행자와 시각을 남긴다.
- 못 한 항목은 사유가 필수다. 사진 필수 항목은 사진 또는 못 한 사유가 있어야 처리된다.

### 항목 관리

- 별도 페이지(`/garden/checklist/items`), 권한은 운영진 또는 가든 탭 `체크리스트 항목 관리`. 탭을 지정하지 않은 계정은 전체 허용 규칙에 따라 포함된다.
- 추가(구역 끝에), 삭제(되돌리기 가능), 손잡이로 끌어서 순서 변경(마우스·터치), 구역 이동·이름 변경.
- 삭제는 행을 남기고 목록에서만 뺀다. 지난 체크 기록이 항목을 참조하기 때문이다. `사용` 끄기는 잠시 쉬는 항목, 삭제는 더 안 쓰는 항목에 쓴다.
- 순서 저장은 조의 목록 전체를 보내, 그사이 다른 사람이 항목을 더하거나 지웠으면 덮어쓰지 않고 새로고침을 안내한다.

### 사진

- 브라우저의 실시간 카메라 스트림에서 찍은 프레임만 받는다. 화면에 파일 선택 입력을 두지 않는다.
- 업로드 전에 긴 변 1280px JPEG로 줄인다. 촬영 시각은 서버가 받은 시각으로 기록한다.
- 사진은 비공개 저장소에 두고, 권한을 검사하는 경로로만 제공한다. 열람은 운영진과 그날 그 조로 제한한다.
- 일일 정리 작업이 90일 지난 사진을 지우고, 체크 기록은 남긴다.
- 한계: 화면에 띄운 옛 사진을 다시 찍거나 API를 직접 조작하는 행위는 막지 못한다.

### 모듈

- **배정 모듈(순수):** 근무, 조 수정값, 대신 맡기, 직원 태그 → 오픈·마감 조원과 책임자. 화면과 DB에 의존하지 않는다.
- **항목 모듈(순수):** 항목 목록과 날짜 → 그날 할 항목(매일, 매주, 매월 첫 요일).
- **제출 판정 모듈(순수):** 항목과 체크 → 남은 항목, 제출 가능 여부.
- **체크리스트 저장소:** 하루치 조회, 체크, 사진, 제출, 다시 열기, 대신 맡기, 항목 관리. 권한 판정 뒤에 서비스 권한으로 접근한다.
- **권한:** 가든 탭 `checklist` 보유자 = 자기 배정분, 대표와 스케줄 작성자 = 운영진.
- **근무 스케줄 화면(수정):** 날짜별 조 구성·책임자 수정.
- **직원 명부 화면(수정):** 책임 태그, 계정 연결. 다른 세션이 활발히 수정 중인 영역이므로 작업 전에 최신 구조를 확인한다.
- **카메라 컴포넌트:** 권한 오류와 미지원 환경을 포함한 촬영·미리보기.

### 스키마

- 항목, 하루 조별 체크리스트, 항목별 체크 표(1차 구현에 있음).
- 추가: 날짜별 조 수정(사람 추가·제외, 책임자), 대신 맡기 기록, 다시 열기 기록, 사진 삭제 시각, 직원 책임 태그.
- 초기 항목은 표가 비어 있을 때만 넣는다. 이미 있으면 절대 덮어쓰지 않는다. 표는 RLS를 켜고 정책 없이 닫는다.
- 항목은 지우지 않고 끈다.

### 판교 초기 항목

| 구분 | 결정 |
|---|---|
| 기준 | 시트 `[Garden Service] 마감 메뉴얼` 대조본 |
| 오픈조 업무 | 분리수거·설거지·착즙기 청소는 오픈 목록의 `퇴근 전`(시각 표기 없음) |
| 삭제 | 오렌지·애플파이 해동 |
| 샤워스크린 | 마감 때 세척·건조, 오픈 때 결합 |
| 호퍼 | 매일 비우기, 세척은 주간 |
| 쿠션 | 매일 오염 확인, 정리는 주간 |
| 화병 | 하루 1회, 낮 업무 |
| 기기 닦기 | 오픈 1회 + 마감 1회 |
| 커틀러리 | 매일 마감 때 통 비우고 세척 후 건조·비치(목요일 항목 삭제) |
| 마감 순서 | 문 잠금 확인이 맨 마지막 |
| 사진 필수 | `샤워스크린 분해·약품 세척`, `타일 바닥 청소기 후 물걸레`, `문 모두 잠금 확인` |
| 제안 항목 | `오븐·식기세척기 전원 끄기`만 켬. 프렙, 냉장고 점검, 포스 마감, 경보 설정은 꺼 둠 |

요일이 없던 주간 업무의 요일과 월간 업무의 `매월 첫 화요일`은 제안값이며, 앱에서 바꿀 수 있다.

### 양재천 초기 항목(제안, 확대 시 확정)

- 판교 목록 복사 + 월요일 업무를 화요일로 이동 + 마감 구역 시각 표기 제거 + 브런치바 세팅·마감 항목(꺼진 상태).
- 시범 중에는 직원에게 노출하지 않는다.

## Testing Decisions

- 좋은 테스트는 입력과 결과만 검증한다. 내부 구현이나 저장 형식에 묶이지 않는다.
- 단위 테스트 대상(프로젝트의 근무 스케줄·교육 테스트와 같은 방식):
  - 배정: 시각 규칙, 조 수정 우선, 실제 근무 우선, 미배포, 다른 지점·날짜, 분할 근무, 휴무일, 대신 맡기
  - 책임자: 태그 우선순위, 입사일·이름 순, 빈 입사일, 지정 우선, 넘기기
  - 항목: 매일, 매주, 매월 첫 요일, 꺼진 항목, 순서
  - 제출: 누락, 사진 필수, 못 한 사유
  - 사진 보관: 90일 경계
- 권한 라우팅 변경은 기존 접근 통제 테스트를 함께 갱신한다.
- 마이그레이션은 운영 적용 전에 임시 Postgres에서 재실행·덮어쓰기 없음을 확인한다.
- 수동 검증(배포 후 시범 전): 아이폰 Safari와 안드로이드 Chrome에서 로그인, 체크, 카메라, 권한 거부, 카카오톡 앱 내 브라우저, 제출, 다시 열기, 대신 맡기, 사진 열람 권한.
