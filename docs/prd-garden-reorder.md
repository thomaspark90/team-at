# PRD — 가든 발주(반복 발주 최저가)

- 상태: **1단계(품목표) 구현 완료 · 미커밋·미배포** (2026-11-26, 운영 DB 마이그레이션 20261126100000 적용, 화면은 배포 후 확인 필요). 2단계(가격 조회)·3단계(발주 화면) 전
- 작성 근거: 2026-11-26 대화(까사디 테이블 최저가 조사 → 반복 발주 도구 제안), 가든 최근 6개월 네이버페이·쿠팡 결제 집계
- 관련: 네이버페이·쿠팡 자동 수집(`/api/finance/naverpay/ingest`, `/api/finance/coupang/ingest`), 원두 발주(`/garden/filtercoffee`)
- 표기: 이 문서의 금액은 모두 원 단위, 결제액은 VAT 포함으로 본다 [가정]. `[제안]`은 확정 전 기본값이다.

## Problem Statement

가든은 버터·밀가루·소시지·소스 같은 재료를 네이버 스마트스토어에서 반복해서 산다. 지금은 발주할 때마다 사람이 검색하고 판매처를 고른다.

- 같은 물건을 매번 다시 찾는 데 시간이 든다.
- 지난번에 얼마에 샀는지, 지금 더 싼 판매처가 있는지 발주 시점에 알 수 없다.
- 같은 품목을 여러 판매처에서 산 기록이 흩어져 있어 단가 변화를 볼 수 없다.

최근 6개월(2026-05-26~11-26) 가든 결제에서 3회 이상 반복된 품목은 약 45개이고, 대부분 네이버페이 결제다. 상위 품목 예: 앵커 버터 454g × 20개(18회, 2,764,200원), 동원 통그릴후랑크 840g × 10개(10회, 1,807,800원), 슈가데일 베이컨 454g × 24개(7회, 1,255,200원).

## Solution

가든 화면에 「발주」를 만든다(주소 `/garden/reorder`). 1차는 양재천만 한다.

1. **품목표**: 결제 기록에서 반복 품목을 뽑아 초안을 만들고, 사람이 품목명·규격·검색어·비교 여부를 다듬는다.
2. **가격 조회**: 비교 대상 품목은 하루 한 번 네이버 쇼핑 검색으로 판매처별 가격을 받아 저장한다.
3. **발주 화면**: 품목마다 지난 구매가, 지금 최저가, 차액을 보여준다. 수량을 넣고 [발주]를 누르면 그 판매처 상품 페이지가 새 탭으로 열린다. 결제는 사람이 한다.

자동 결제는 하지 않는다. 구매자용 주문 API가 없어 로그인·결제를 브라우저 자동화로 해야 하고, 잘못 주문되면 돈이 나가기 때문이다.

## User Stories

### 발주 담당

1. 발주 담당으로서, 자주 사는 재료 목록을 한 화면에서 보고 싶다. 매번 검색하지 않기 위해서다.
2. 발주 담당으로서, 품목마다 지난 구매가와 지금 최저가를 나란히 보고 싶다. 어디서 살지 바로 정하기 위해서다.
3. 발주 담당으로서, 가격을 단위당(100g당, 1L당, 개당)으로도 보고 싶다. 묶음과 용량이 다른 상품을 같은 기준으로 비교하기 위해서다.
4. 발주 담당으로서, 수량을 넣고 [발주]를 누르면 판매처 상품 페이지가 열리길 원한다. 찾는 단계를 건너뛰기 위해서다.
5. 발주 담당으로서, 여러 품목을 담아 한 번에 판매처별로 묶어 보고 싶다. 같은 판매처 주문을 합쳐 배송비를 줄이기 위해서다.
6. 발주 담당으로서, 가격 비교를 하지 않는 품목(채소·다짐육·주문제작)은 지난번 판매처 링크만 보고 싶다. 다른 물건이 최저가로 뜨는 혼동을 피하기 위해서다.
7. 발주 담당으로서, 처음 보는 판매처가 최저가일 때는 `확인 필요` 표시를 보고 싶다. 다른 규격이나 유통기한 임박 상품을 잘못 사지 않기 위해서다.
8. 발주 담당으로서, 가격을 마지막으로 조회한 시각을 보고 싶다. 오래된 가격을 믿지 않기 위해서다.
9. 발주 담당으로서, 내가 누른 발주 기록(품목·수량·판매처·그때 가격)을 다시 보고 싶다. 무엇을 주문했는지 확인하기 위해서다.

### 운영진

10. 운영진으로서, 결제 기록에서 자동으로 뽑힌 품목 후보를 승인하거나 버리고 싶다. 품목표를 처음부터 손으로 만들지 않기 위해서다.
11. 운영진으로서, 품목의 이름·규격·검색어·필수 포함어·제외어를 고치고 싶다. 같은 물건만 비교되게 하기 위해서다.
12. 운영진으로서, 품목별로 믿는 판매처를 지정하고 싶다. 그 안에서만 최저가를 고르게 하기 위해서다.
13. 운영진으로서, 품목에 지점을 달아 두고 싶다. 1차는 양재천만 쓰지만 판교로 넓힐 때 품목표를 다시 만들지 않기 위해서다.
14. 운영진으로서, 품목별 단가 추이를 보고 싶다. 가격이 오른 재료를 알아채기 위해서다.
15. 운영진으로서, 발주 화면을 볼 수 있는 계정을 가든 탭 권한으로 정하고 싶다. 기존 권한 방식과 맞추기 위해서다.

## Implementation Decisions

### 품목과 같은 물건 판정

- 품목 한 줄은 `이름 · 규격(단위 수량 × 묶음) · 기준 단위 · 검색어 · 필수 포함어 · 제외어 · 비교 여부 · 지점`으로 이뤄진다.
  - 예: 앵커 버터 / 454g × 20개 / 100g당 / 검색어 `앵커 버터 454g 20개` / 필수 `앵커, 454` / 제외 `무염 가염 중 쓰지 않는 쪽`.
- 초안은 `finance.transactions`에서 `bank in (naverpay, coupang)`, `brand = garden`, 양재천 수령 건, 최근 6개월, 3회 이상 반복된 상품명으로 만든다. 상품명 뒤의 `@수령인`, `외 n건`, `🔍미해석` 꼬리는 떼고 묶는다.
- 결제 기록에는 건당 총액만 있고 수량이 없다. 지난 구매가는 **가장 최근 결제의 총액**으로 보여주고, 단위당 가격은 품목표의 규격을 사람이 확정한 뒤에만 계산한다.
- 검색 결과는 제목에 필수 포함어가 모두 있고 제외어가 없는 것만 후보로 삼는다. 제목에서 규격을 읽을 수 있으면 품목 규격과 같은 것만 남긴다.
- 판매처는 세 상태로 둔다: `믿는 판매처`(운영진이 승인), `확인 필요`(아직 승인하지 않은 곳), `제외`.
  - 1차는 구매 이력이 있는 판매처도 하나씩 승인한다(2026-11-26 대표 결정). 돌려 본 뒤 구매 이력 판매처 자동 승인으로 바꾼다.
  - 화면의 기본 최저가는 믿는 판매처 안에서 고른다. 확인 필요 판매처가 더 싸면 그 가격을 따로 한 줄 보여준다.

### 가격 조회

- 네이버 쇼핑 검색 API를 쓴다. 호출 한도는 하루 25,000회로 알려져 있으나 공식 문서로는 확인하지 못했다. 착수할 때 확인한다.
- 품목 50개 × 하루 1회면 하루 50회 수준이라 한도와 무관하다.
- 조회 주기: 하루 한 번(새벽) + 발주 화면의 `지금 다시 조회` 버튼 [제안].
- 조회할 때마다 품목·판매처·가격·상품 링크·조회 시각을 한 줄씩 쌓는다. 단가 추이는 이 기록에서 그린다.
- API 키는 네이버 개발자센터에서 앱을 등록해 발급받아야 한다. 계정 생성과 키 발급은 대표가 직접 한다.
- 한계: 검색 API의 가격에는 **배송비가 들어 있지 않다**. 품목·판매처별 배송비는 사람이 입력한 값만 반영하고, 입력이 없으면 `배송비 미확인`으로 표시한다.
- 한계: 쿠팡 가격은 조회하지 않는다. 구매자용 공식 API가 없다. 쿠팡에서 사는 품목은 지난 구매가와 링크만 보여준다.

### 발주 흐름

- [발주]를 누르면 발주 기록 한 줄(누가·언제·품목·수량·판매처·그때 표시가)을 남기고 상품 페이지를 새 탭으로 연다.
- 수량은 기록과 화면 안내용이다. 판매처 페이지에 수량을 자동으로 넣지 않는다 [제안]. 스마트스토어 주소로 수량을 넘기는 공식 방법이 확인되지 않았다.
- 여러 품목을 담으면 판매처별로 묶어 보여주고, 판매처마다 링크를 하나씩 연다.
- 발주 기록과 이후 들어오는 네이버페이 결제 건을 자동으로 짝짓는 일은 1차 범위에서 뺀다.

### 권한

- 발주 화면과 품목 관리 모두 대표·매니저만 쓴다(2026-11-26 대표 결정). 가든 탭 권한 키를 새로 만든다 [제안: `reorder`].
- 화면 이름이 「발주」라 기존 「원두 발주」와 헷갈릴 수 있다. 메뉴에서는 둘을 나란히 두지 않거나 설명 한 줄로 구분한다.
- 가든 메뉴(`GARDEN_NAV`)에 항목을 더하면 알림 토픽 묶음 테스트도 함께 고친다.

### 모듈

- **품목 추출(순수):** 결제 기록 → 반복 품목 후보. 상품명 꼬리 제거와 묶기 규칙을 여기에 둔다.
- **규격 해석(순수):** 상품 제목 → 단위 수량·묶음 수·총량. `454g × 20개`, `10kg`, `1L 12개`, `840gx10개` 같은 표기를 읽는다.
- **후보 판정(순수):** 품목 + 검색 결과 → 같은 물건 후보와 판매처 상태, 단위당 가격.
- **가격 조회기:** 네이버 쇼핑 검색 호출과 응답 정리. 키와 호출은 서버에서만 한다.
- **저장소:** 품목, 판매처 상태, 가격 기록, 발주 기록.
- **발주 화면 · 품목 관리 화면.**

### 스키마(제안)

- `reorder_items`: 품목(이름, 규격, 기준 단위, 검색어, 필수 포함어, 제외어, 비교 여부, 지점, 사용 여부)
- `reorder_sellers`: 품목 × 판매처 상태(믿는 판매처·확인 필요·제외), 배송비(원)
- `reorder_prices`: 조회 기록(품목, 판매처, 가격(원), 상품 링크, 제목, 조회 시각)
- `reorder_orders`: 발주 기록(누가, 언제, 품목, 수량, 판매처, 표시가(원))

## Testing Decisions

- 순수 모듈 세 개(품목 추출, 규격 해석, 후보 판정)는 실제 결제 기록의 상품명과 검색 결과 제목을 예시로 단위 테스트한다.
- 규격 해석은 틀리면 단위당 가격이 통째로 틀어지므로, 읽지 못한 제목은 추측하지 않고 `규격 미확인`으로 떨어지는지 확인한다.
- 가격 조회기는 저장해 둔 응답으로 테스트하고, 실제 호출은 수동 점검으로 둔다.

## Out of Scope

- 자동 결제, 장바구니 자동 담기
- 이미지로 같은 물건 찾기(가구·집기 같은 일회성 구매는 그때그때 따로 조사)
- 쿠팡·기타 몰 가격 조회
- 재고·사용량과 연동한 발주 수량 추천
- 채소·과일·다짐육·주문제작품의 최저가 비교(지난 판매처 링크만 제공)
- 스탭밀·개인 브랜드 품목

## Further Notes

### 단계

1. 품목표 초안 추출과 품목 관리 화면
2. 가격 조회와 기록
3. 발주 화면과 발주 기록

### 효과 확인

- 비교 대상 품목에 대해 `지난 구매가 − 발주 시점 최저가`를 발주 기록에 남겨, 월별 절감액(원)을 집계한다.
- 엘르앤비르 고메 버터 10kg처럼 판매처 세 곳이 모두 227,400~227,500원인 품목은 비교 효과가 없을 수 있다. 한 달 돌려 보고 효과 없는 품목은 비교를 끈다.

### 결정된 사항(2026-11-26 대표)

- 화면 이름은 「발주」.
- 1차는 양재천만 진행한다.
- 대표·매니저만 쓴다.
- 판매처는 하나씩 승인하고, 추후 자동 승인으로 넘어간다.

### 확인이 남은 사항

- 가든 쿠팡 결제가 2026-09-30 이후 기록에 없다. 쿠팡 발주를 그만둔 것인지 수집이 멈춘 것인지 확인이 필요하다.
- 네이버 쇼핑 검색 API의 호출 한도와 응답 항목(판매처 이름, 상품 번호)을 공식 문서로 확인.
- 네이버 개발자센터 앱 등록과 키 발급(대표가 직접).
